# 매너온도(찾길 온도) 기획 스펙 — 찾기 완료 → 후기 작성 유도 → 후기 작성

> 원본: Confluence 위키 (인증 필요로 직접 열람 불가하여 사용자가 텍스트로 전달, 2026-09-29 기준)
>
> 관련 라우트: 이 파일이 다루는 흐름은 `chat/[postId]`(찾기 완료 버튼) → `PostFoundConfirmModal`
> (도메인 컴포넌트, 후기 작성 유도 모달) → `write/review/[roomId]`(찾길 후기 작성)로 이어진다.
> `list/[id]`의 `PostActionMenu`도 같은 `PostFoundConfirmModal`을 재사용한다.
>
> 참고: 작성된 후기의 감정 뱃지/도움 경험/상세 후기 노출 방식은 마이페이지 > 찾길 온도 > 찾길 후기
> (받은 후기/보낸 후기) 디스크립션에 별도로 정의되어 있음 (아직 미확보).

## 1. 분실물 찾기 완료

### 1-1. [분실물 찾기 완료] 버튼

분실자가 실제 물건을 찾아준 사용자와의 1:1 채팅방에서 [분실물 찾기 완료] 버튼을 선택할 수 있다.

**노출 조건**

- 게시글 상태가 "찾는 중"인 경우 [분실물 찾기 완료] 버튼 노출
- 게시글 상태가 "찾음"인 경우 [분실물 찾기 완료] 버튼 미노출

**[분실물 찾기 완료] 버튼 선택 시**

- 해당 게시글 상태를 "찾음"으로 변경
- [분실물 찾기 완료] 버튼 미노출 처리
- [분실물 찾기 완료]를 선택한 채팅방의 상대방을 실제 도움 사용자로 반영
- 도움을 준 사용자의 도움 경험 및 찾길 온도 반영
- 후기 작성 유도 모달 노출 (아래 2절)

**정책**

- [분실물 찾기 완료] 처리 이후 다시 "찾는 중" 상태로 변경할 수 없음
- 동일한 분실물 건에 대해 [분실물 찾기 완료]를 중복 처리할 수 없음
- 완료 처리 이후 도움을 준 사용자를 다른 사용자로 변경할 수 없음

※ 게시글 상태 변경 기준은 [공통_게시글 상태 정책] 참고
※ [분실물 찾기 완료]에 따른 도움 경험 및 찾길 온도 반영 기준은 [공통_찾길온도_정책] 참고
(두 공통 정책 문서 모두 아직 미확보)

## 2. 후기 작성 유도

### 2-1. 후기 작성 유도 모달

[분실물 찾기 완료] 처리 후, 도움을 준 상대방에게 후기를 작성할 수 있도록 후기 작성 유도 모달을
노출한다.

**노출 정보**

- 타이틀: "고마운 마음을 후기로 남겨볼까요?"
- 안내 문구: "물건을 찾는 데 도움을 준 상대방에게 고마웠던 마음을 후기로 남겨주세요."
- [나중에] 버튼
- [후기 남기기] 버튼

**[나중에] 선택 시**

- 후기 작성 유도 모달 닫힘
- 현재 채팅방 유지
- 게시글 상태는 "찾음" 상태로 유지
- [분실물 찾기 완료] 버튼을 [후기 작성하기] CTA 버튼으로 변경 (4절)
  - [후기 작성하기] 선택 시 3절(찾길 후기 작성 페이지)로 이동

**[후기 남기기] 선택 시**

- 3절(찾길 후기 작성 페이지)로 이동

## 3. 찾길 후기 작성

### 3-1. 감정 유형 선택 (필수 입력)

도움을 준 상대방과의 경험에서 느낀 감정을 선택한다.

**선택 항목**: 감동 / 감사 / 심쿵

**정책**

- 3개 항목 중 1개만 선택 가능
- 다른 감정 유형 선택 시 기존 선택값 해제 후 신규 항목 선택
- 선택한 감정 유형은 후기 정보에 반영
- 선택한 감정 유형은 후기 목록 및 후기 상세 화면의 감정 뱃지에 사용

### 3-2. 도움 경험 선택 (필수 입력)

상대방에게 어떤 도움을 받았는지 해당하는 항목을 선택한다.

**선택 항목**

- 친절하고 따뜻하게 대해주셨어요.
- 믿고 소통할 수 있었어요.
- 빠르게 연락해 주셔서 도움이 됐어요.
- 물건을 안전하게 보관해 주셨어요.
- 물건을 찾을 수 있도록 정보를 알려주셨어요.

**정책**

- 최소 1개 이상 선택 필수
- 복수 선택 가능
- 선택된 항목 재선택 시 선택 해제
- 선택한 도움 경험은 후기 정보에 반영

### 3-3. 후기 작성 (선택 입력)

도움을 준 상대방에게 전달할 상세 후기를 작성할 수 있다.

**입력 정책**

- 선택 입력
- 최대 300자까지 입력 가능
- 입력한 글자 수를 N/300 형식으로 노출
- 상세 후기를 작성하지 않아도 필수 입력 항목이 모두 선택된 경우 후기 등록 가능

### 3-4. [후기 남기기] 버튼

필수 입력 항목 충족 여부에 따라 [후기 남기기] 버튼 상태를 변경한다.

**비활성화 조건** (하나라도 해당 시 비활성화)

- 감정 유형을 선택하지 않은 경우
- 도움 경험을 1개 이상 선택하지 않은 경우

**활성화 조건**

- 감정 유형 1개 선택
- 도움 경험 1개 이상 선택

**[후기 남기기] 선택 시**

- 입력한 후기 정보 등록
- 정상 등록 완료 시 3-5(후기 작성 완료 팝업) 노출

### 3-5. 후기 작성 완료

후기가 정상적으로 등록된 경우 후기 작성 완료 팝업을 노출한다.

**노출 정보**

- 후기 작성 완료 타이틀
- 후기 등록 완료 안내 문구
- [후기 작성 완료] 버튼

**[후기 작성 완료] 선택 시**

- 완료 팝업 닫힘
- 후기 작성 완료 상태로 변경
- 이전 화면으로 이동
- 채팅방 내 [후기 작성하기] 버튼 미노출
- 동일한 찾기 완료 건에 대해 후기 중복 작성 불가

## 현재 구현과의 차이 (구현 시 반영 필요)

이 스펙을 받기 전에 이미 구현된 부분과 다른 지점들. 후속 작업 시 이 스펙 기준으로 맞춰야 한다.

- **[나중에] 선택 시 상태 변경 여부**: 스펙은 "게시글 상태는 찾음 상태로 유지"라고만 되어 있고, 게시글
  상태 변경 자체(SEARCHING→FOUND)는 이미 1-1에서 처리 완료된 것으로 서술한다. 현재 구현
  (`PostFoundConfirmModal`)은 "나중에"/"후기 남기기" 두 버튼 모두에서 상태 변경(`putPostStatus`)을
  호출하는데, 스펙대로면 모달이 뜨는 시점에 이미 상태가 "찾음"으로 바뀌어 있어야 하므로 모달의 두 버튼은
  상태 변경을 다시 호출할 필요가 없어야 한다. 현재는 모달을 여는 진입점(`ChatRoomHeaderInfoButton`의
  "분실물 찾기 완료" 클릭, `PostActionMenu`의 "찾기 완료로 변경" 클릭)에서 상태 변경 없이 모달만 열고,
  모달의 두 버튼 클릭 시점에 비로소 상태를 변경하는 구조라 스펙과 순서가 다르다.
- **[나중에] 선택 후 CTA 버튼 전환**: 스펙은 "찾기 완료" 버튼이 [후기 작성하기] CTA로 바뀐다고
  명시하지만, 현재 `ChatRoomHeaderInfoButton`의 케밥 메뉴에는 이 전환 로직이 없다. "찾기 완료" 상태가
  된 이후 케밥 메뉴에서 해당 항목이 어떻게 바뀌어야 하는지(미노출/라벨 변경/CTA 전환 위치가 케밥 메뉴인지
  다른 곳인지) 추가 확인 필요.
- **후기 작성 완료 팝업(3-5)**: 아직 구현 안 됨. 현재는 후기 등록 API 자체가 없어 제출 로직이 비어있는
  상태.
- **후기 작성 완료 후 "채팅방 내 [후기 작성하기] 버튼 미노출" / "후기 중복 작성 불가"**: 후기 작성 여부를
  프론트에서 어떻게 판별할지(게시글/채팅방 응답에 포함될 필드) 백엔드 계약 확인 필요.
- **감정 유형 선택 UI**: 스펙과 현재 구현(`ReviewFeelingSelect`) 일치 — 3개 중 단일 선택, 재선택 가능.
- **도움 경험 선택 UI**: 스펙과 현재 구현(`ReviewHelpChecklist`) 일치 확인 완료 — `ko.json`의
  `ReviewWritePage.helpItems` 5개 문구가 이 문서 3-2 항목과 정확히 동일.
